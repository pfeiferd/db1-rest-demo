DB1 – REST-Demo

Begleitprojekt zum Kapitel „Von der Datenbank zum Informationssystem“. Lesende Operationen (GET) sind einfache Links. Für POST, PUT und DELETE schicken die Knöpfe den Request mit JavaScript (fetch) – Request und Response erscheinen unten in der Ausgabe.

1. Artikelarten – ressourcenorientiert (REST)

Klasse demo.lager.ArtikelartResource, Daten im Hauptspeicher.

GET/api/artikelarten – alle Artikelarten
GET/api/artikelarten?maxGewicht=1 – mit Filter (@QueryParam)
GET/api/artikelarten/A1 – eine Artikelart (@PathParam)
GET/api/artikelarten/A9 – gibt es nicht: 404 Not Found
POST – anlegen: 201 Created mit Location; mit "gewicht": 0 gibt es 400 Bad Request
PUT /api/artikelarten/ – ändern (zweimal hintereinander: gleiches Ergebnis, idempotent)
DELETE /api/artikelarten/ – löschen: 204 No Content, beim zweiten Mal 404

2. PersonService – Studie im Stil von gweb (RPC-Stil über HTTP)

Kette PersonRestService → PersonRoleService → PersonCacheService → PersonJDBCService mit einer H2-Datenbank im Hauptspeicher. Angemeldet ist für die Demo immer eine Admin-Person (DemoUserStore).

GET/api/PersonService/getAll – alle Personen
GET/api/PersonService/get/1 – eine Person (zweiter Aufruf kommt aus dem Cache)
GET/api/PersonService/get/99 – gibt es nicht: 404
POST – liefert die neue ID
PUT – Write-Through: erst Datenbank, dann Cache
DELETE /api/PersonService/remove/

Ausgabe

Noch kein Request gesendet.
