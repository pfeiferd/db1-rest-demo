DB1 – REST-Demo

Begleitprojekt zum Kapitel „Von der Datenbank zum Informationssystem“. Lesende Operationen (GET) sind einfache Links. Für POST, PUT und DELETE schicken die Knöpfe den Request mit JavaScript (fetch) – Request und Response erscheinen unten in der Ausgabe.

1. Personen – ressourcenorientiert (REST)

Klasse demo.personen.PersonResource, Daten im Hauptspeicher.

GET/api/personen – alle Personen
GET/api/personen?lastName=Turing – mit Filter (@QueryParam)
GET/api/personen/1 – eine Person (@PathParam)
GET/api/personen/99 – gibt es nicht: 404 Not Found
POST – anlegen: 201 Created mit Location; ohne lastName gibt es 400 Bad Request
PUT /api/personen/ – ändern (zweimal hintereinander: gleiches Ergebnis, idempotent)
DELETE /api/personen/ – löschen: 204 No Content, beim zweiten Mal 404

2. PersonService – Studie im Stil von gweb (RPC-Stil über HTTP)

Dieselben DTOs, aber mit Dienstschnittstelle und Pfaden im RPC-Stil wie in gweb. Kette PersonRestService → PersonRoleService → PersonCacheService → PersonJDBCService mit einer H2-Datenbank im Hauptspeicher. Angemeldet ist für die Demo immer eine Admin-Person (DemoUserStore).

GET/api/PersonService/getAll – alle Personen
GET/api/PersonService/get/1 – eine Person (zweiter Aufruf kommt aus dem Cache)
GET/api/PersonService/get/99 – gibt es nicht: 404
POST – liefert die neue ID
PUT – Write-Through: erst Datenbank, dann Cache
DELETE /api/PersonService/remove/

Ausgabe

Noch kein Request gesendet.
